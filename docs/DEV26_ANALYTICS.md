## Measured gap and consumers

The actual Dev REST container sets `PGRST_DB_MAX_ROWS=1000`. At baseline, personal/global dashboards called table-returning facts RPCs, so a successful response can silently omit later participations. Their consumers reconstruct all aggregates and streaks in JavaScript. The web dashboard/global-admin path also schedules commander-color provider enrichment. Native statistics uses the same facts adapter; native profile performance had a silent fallback to a potentially capped raw participant query. None of those paths can certify complete results merely from HTTP200.

The new dashboard RPCs return a single JSON object with schemaVersion2, complete=true, snapshot time, explicit scope and period filters. SQL aggregates all matching rows before constructing bounded top10/best-deck cards, color/bracket/win-condition groups, distinct deck count and streaks. Payload grows with aggregate groups rather than match count. Personal authorization is self/admin; global access is service-only behind the existing admin API. Private helpers grant no anonymous/authenticated/service direct execution. A separate JSON wrapper protects profile deck rollups from the table row cap. New clients must validate the version and complete contract and display errors for incompatible/failed backends; no fallback to capped facts or manufactured zeros.

## Product semantics to preserve

- Personal totals are the signed-in user's participations. Global totals are registered-user participations after existing demo/admin exclusions; they are not distinct match totals. Both participation and distinct-match counts are explicit.
- Draws remain in total games and outside the decisive-game denominator. Wins on a drawn legacy row cannot count twice. Top-deck ordering uses the existing whole-percentage win rate, games and wins; best deck retains its current3-game minimum. Unique IDs break equal ranks deterministically.
- Historical participant snapshots take precedence over current deck metadata. Deletion's existing historical identities remain intact; archived/occasional decks count. Older unlinked rows remain in totals and color/bracket aggregates, but cannot be invented into a known deck identity or unique-deck count. Their number is explicit.
- Guest-only rows retain their existing exclusion from global registered-user metrics. Existing arena analytics continues to include guests according to its group contract. Linked guest deck identities use a separate namespace.
- Color and bracket groups use each historical fact's snapshot. Unknown colors are counted explicitly; no provider request or current metadata may silently recolor historical facts. Percentages continue to use color appearances, so multicolor participations appear in multiple colors.
- Streaks ignore draws. Equal timestamps use match and participant IDs. Missing legacy timestamps make chronology incomplete and preserve the existing zero-valued internal streaks with explicit metadata.
- Filters use `[since, until)` timestamps and the historical bracket. Table size stays with match/group contexts that actually expose it; dashboard queries do not calculate unused per-match participant counts or invent original table sizes for legacy records.
